The sequence

Nine steps, any page

This is the weave. Architecture steps and copy steps in the order they actually happen. Do not start step 4 before step 3 is signed off, or you will pay for it twice.

Architecture — you Copy — Crimson
Architecture

Lock the page spec

URL, what it owns, one job, one CTA, target lifecycle stage. If you cannot state the job and the CTA in one sentence each, the page is not scoped and copy cannot start.

Architecture

Write the section order

The numbered outline the copy will follow. This is what makes the draft mappable to modules later. It already exists for all 17 assets in the briefs.

Copy

Outline, approved before drafting

Section headers plus the lead sentence and the intended mantra. Not optional on pillar pages. Cheapest place to catch a wrong direction.

Copy

Draft 1 with the machine layer

Body copy plus SEO title, meta description with character count, FAQ pairs in complete sentences, alt text, and internal links marked inline with intended anchor text.

Copy

Draft 2, voice pass

Revisions plus a Blue Lake Ideas voice check against the style guide. Final language governance happens here.

Architecture

Build to the section order

Assemble from the module library. Section headings map one to one with the brief so nothing gets reordered in the build.

Architecture

Wire the links both directions

Cluster links up to its pillar with exact-term anchor text. Pillar links down to the new cluster page. A page with no inbound link from its pillar is orphaned and will not rank.

Architecture

Ship the machine layer

FAQ schema matching visible answers word for word, canonical tag, breadcrumbs on Level 2, one H1 containing the owned term, alt text on framework graphics.

Architecture

Publish and record

Run the link audit test. Record URL and publish date in the Command Center against the term. Then the page is done.

Standards

Rules you enforce

Open as needed. These are the checks that fail a page at step 7 or 8.

Internal linking law five rules, no exceptions
  1. Cluster links up, always. Every cluster page links to its pillar in the body, using the exact owned term as anchor text. Not "read more."
  2. Pillar links down, always. Every pillar links out to each cluster page. No inbound link from the pillar means orphaned.
  3. Never cross-link cluster to cluster. Route through the pillar. Cross-links dilute which page owns which term.
  4. First mention links, later mentions do not. Subsequent appearances are plain text.
  5. Commercial pages receive, they do not distribute. Speaking, Workshops, Certification, Advisory link back up to pillars but never sideways to each other.

The link audit test

Open any published page at random. Can you reach the correct canonical definition of every owned term it uses in one click? If not, the page is not finished. Run monthly.

  • Person schema on /about, nested inside Organization, Matt as founder and author
  • Article schema on every Insights post with the pillar as mainEntityOfPage
  • Book schema on /overloaded

  • Framework graphics carry alt text naming the move and the cycle
  • Largest Contentful Paint under 2.5 seconds on mobile
  • XML sitemap auto-generated and submitted, excluding form pages and audit result variants
Why this matters more than usual here

Blue Lake Ideas is trying to own vocabulary that does not yet exist. AI answer engines resolve unfamiliar terms by finding a source that defines them cleanly and consistently. Visible FAQs with matching schema, one canonical page per term, and consistent anchor text decide whether the firm gets cited as the definition or paraphrased into someone else's.
